# CLAUDE.md — compliance-base

Per-repo compliance compiler: turns GDPR / SOC 2 / ISO 27001 prose into a
machine-readable constraint catalog, derives technical **capabilities** from it,
and validates PRP plans against the result. See the root
[CLAUDE.md](../CLAUDE.md) for the repo-wide picture and [AGENTS.md](AGENTS.md)
for the extraction and validation specification the agents follow.

Everything this engine produces lands under `compliance-base/catalog/`, inside
the repository — never under `.claude/`.

## Commands

```bash
uv sync --directory compliance-base                     # after install/upgrade

/neurawork-cc-harness:co-extract                        # (re)extract the framework catalog
/neurawork-cc-harness:co-capabilities                   # constraints -> capabilities
/neurawork-cc-harness:co-validate <plan>                # validate one PRP plan

uv run --directory compliance-base python scripts/stack.py --scaffold
```

Extraction and deep validation call the Claude Agent SDK and need
`ANTHROPIC_API_KEY` or `CLAUDE_CODE_OAUTH_TOKEN`. Install, the `co-post-tooluse`
hook, and the inline structural precheck work without any key.

Upgrading in place is an adopt/refresh install — it does **not** re-extract:

```bash
python3 <plugin>/engines/compliance-compiler/recon.py                     # read-only
python3 <plugin>/engines/compliance-compiler/install.py --catalog-dir compliance-base
uv sync --directory compliance-base
```

## Configuration (`config.json`)

| Key | Current value | Meaning |
|---|---|---|
| `catalog_dir` | `compliance-base` | This engine's directory name |
| `model` | `""` | Empty means "let the SDK choose" |
| `frameworks` | `["gdpr"]` | Which frameworks are processed — the **filter**, not the catalog |
| `validate_frameworks` | `[]` | Empty means: use `frameworks` |
| `max_concurrency` | `12` | Parallel extraction agents |
| `validate_mode` | `warn` | `warn` or `block` for the plan gate |

`frameworks` is a processing filter. `catalog/` keeps soc2 and iso27001 in full
even while only gdpr is active — see the root CLAUDE.md decision on catalog
completeness.

│   ├── cap_lib.py         capability derivation helpers
│   ├── stack.py           SINGLE SCHEMA OWNER of catalog/stack.json + gap report
│   ├── rules_block.py     renders the marker-owned rules block (engine 5)
│   ├── validate.py        deep plan validation
│   ├── precheck.py        inline structural check used by the hook
│   ├── config.py          paths + config
│   └── utils.py
├── catalog/

│   ├── gdpr.json          127 constraints (109 mandatory)

│   ├── iso27001.json      72 constraints (59 mandatory)

`catalog/*.json` and `catalog/index.md` are **tracked**. Gitignored runtime:
`catalog/.shards/`, `reports/`, `scripts/state.json`, `scripts/last-extract.json`,
`scripts/*.log`.

Engine 5 added `catalog/stack.json` and `scripts/rules_block.py`, and dropped
`_shared/tests/test_manifest.py` and `test_version_check.py` (which the two
documentation engines still carry).

## `stack.py` is the only writer of `stack.json`

Every other pass — including all of `stack-base` — mutates `stack.json` by handing
`stack.py` a payload:

```bash
uv run --directory compliance-base python scripts/stack.py --scaffold
uv run --directory compliance-base python scripts/stack.py --apply-scope    <PATH>
uv run --directory compliance-base python scripts/stack.py --apply-ranking  <PATH>
uv run --directory compliance-base python scripts/stack.py --apply-selection <PATH>
```

Machine-owned fields (`capability`, `framework`, `mandatory_linked`, `options`)
are regenerated by `--scaffold`; human/agent decisions (`chosen`, `rationale`,
`applicable`, `applicability_reason`, `ranked`) survive it.

## Gotchas

- **Do not run `--scaffold` in this repo right now.** It derives the framework set
  from `capabilities.json` and ignores `config.json`'s `frameworks`, so it
  re-injects the 43 soc2/iso27001 keys into `stack.json`. Filed upstream as
  howtobuildsoftware2026 #46. `/st-rank` and `/st-select` do not need it.
- **A fresh scaffold's gap report is legitimately empty of decisions.** After the
  engine upgrade every mandatory-linked capability was undecided; resolve with
  `/neurawork-cc-harness:st-select` before relying on stack data.
- **Commit the catalog before bulk edits.** These files are large and generated —
  git was the only recovery path from a 2127-line accidental deletion.
- **`stack.json` carries a `capabilities_hash`.** If `capabilities.json` is
  regenerated, `stack.py` reports the stack as stale.
